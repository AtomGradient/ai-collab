## 阶段完成与留痕规则

用户于 2026-08-06 明确要求：每个阶段完成后更新 tracked 进度、commit 并 push，以支持在其他机器继续开发；Harness 重构尚未完成时，不得影响其他同事的正常开发节奏。

一个 required gate 或用户指定里程碑只有在适用条件全部满足后，才能在本账本标记为 `completed`：

1. 实现已形成固定 commit 并 push，不 review moving working tree；
2. 按项目协作协议需要 peer review 时，固定 commit 已取得无阻塞 verdict；
3. 需要机器级 witness 的 gate 已生成正式 evidence，并复核 current view 摘要、文件权限和清理状态；
4. 本账本记录实现 SHA、review response、正式 run ID、evidence SHA-256、input fingerprint 和下一 gate，随后再次 commit 并 push。

实现 commit 可以先于正式 receipt 推送，但不能因此把 gate 写成 `completed`。账本 commit 是历史留痕，不替换正式 evidence，也不改变 evidence 所锚定的实现 SHA。

## 跨机器续接边界

- Git 只携带历史进度、固定 SHA 和非敏感 evidence 引用；本机 receipt 不具备跨机器可移植性。
- 在新机器上，应从远端当前续接 commit 开始，先核对 tracked 账本和 gate registry，再重新运行适用于该机器的平台 verifier。旧机器的 `passed` 不能推导新机器也已通过。
- 不复制 `.ai-mailbox/`、receipt 私有目录、credential、完整 session identity 或系统授权状态来伪造续接。
- 不自动修改同事的 worktree、分支、iTerm 窗口、后台服务或系统权限；disposable spike 使用自己的隔离安装/state 范围，并在失败时 fail closed。
